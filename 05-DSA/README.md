# DSA — parallel interview preparation

Keep DSA running alongside System Design. For product-company interviews, a strong HLD/LLD plan does not replace coding-round preparation.

## Recommended cadence

Target **3–4 sessions per week, 30–45 minutes each** if time permits. With a strict 5–7 hour total weekly budget, reserve at least 1.5–2 hours for DSA and reduce passive video time.

## Ordered topic roadmap

| Order | Topic | Practice focus |
|---:|---|---|
| 1 | Arrays and strings | traversal, prefix sums, two pointers |
| 2 | Hash maps and sets | frequency, lookup, grouping |
| 3 | Sliding window | fixed and variable windows |
| 4 | Stack and queue | monotonic stack, BFS queue |
| 5 | Binary search | boundaries, answer-space search |
| 6 | Linked lists | reversal, fast/slow pointers |
| 7 | Trees and BST | DFS, BFS, recursion |
| 8 | Heaps | top-K, merge K lists |
| 9 | Graphs | BFS, DFS, topological sort, shortest paths |
| 10 | Backtracking | subsets, permutations, combinations |
| 11 | Greedy | intervals, scheduling |
| 12 | Dynamic programming | 1D, 2D, subsequences |
| 13 | Tries and union-find | prefix search, connectivity |
| 14 | Mixed timed practice | interview-style sets |

## Problem-solving rules

For each problem:
- [ ] State brute-force approach first.
- [ ] Explain the optimisation.
- [ ] State time and space complexity.
- [ ] Code without copying.
- [ ] Test normal, boundary, and empty inputs.
- [ ] Re-solve after 3–7 days if it was difficult.

Track problems in `DSA-TRACKER.md`. Prioritise understanding over raw problem count.
