# 24-week roadmap

**Goal:** Prepare for product-company HLD and LLD interviews while developing sound engineering judgement.
**Starting point:** Intermediate — APIs, databases, and client-server architecture.
**Time:** 5–7 hours/week.
**Split:** Approximately 65% HLD / 35% LLD, with DSA practice in parallel.

| Phase | Weeks | Focus | Main deliverable |
|---|---:|---|---|
| 1 | 1–4 | Interview foundations | URL shortener design |
| 2 | 5–8 | Distributed systems | Notification service |
| 3 | 9–12 | Classic HLD problems | Chat, feed, video, ride-hailing designs |
| 4 | 13–16 | LLD and machine coding | Four object-oriented designs |
| 5 | 17–20 | Advanced HLD and trade-offs | Payment system design |
| 6 | 21–24 | Interview simulation | Design portfolio and mock reviews |

## Weekly cadence

- **Learn:** 2 hours.
- **Read / documentation:** 1 hour.
- **Build:** 1.5 hours.
- **Design problem or DSA:** 1.5 hours.
- **Review:** 1 hour.

## Phase outcomes

### Phase 1 — Foundations
Clarify requirements, estimate scale, select data stores, and explain caching, load balancing, and API boundaries.

### Phase 2 — Distributed systems
Reason about consistency, asynchronous messaging, retries, idempotency, partitioning, and failure recovery.

### Phase 3 — Classic HLD
Practise common interview prompts using a repeatable 45–60 minute framework.

### Phase 4 — LLD
Model domain objects, apply SOLID and patterns appropriately, handle concurrency, and write extensible code.

### Phase 5 — Advanced HLD
Explain transactions, reliability, observability, capacity, security, and trade-offs.

### Phase 6 — Interview simulation
Practise communication under time constraints, identify weak areas, and revise deliberately.
